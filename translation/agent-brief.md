# 第二版翻譯代理的工作指引

你負責把《精通以太坊》第二版的**一個檔案**翻譯成台灣繁體中文。這份指引是你唯一的背景資料，請完整讀完再開始。工作目錄是 repo 根目錄（`/Users/doge/github/ethereumbook_zh`）。

## 開始前先讀

1. `upstream/<你的檔案>`：英文原稿（上游 5907a8c，**不要修改**）。
2. `translation/style-guide.md`：風格指南，尤其是「結構規則」一節。
3. `translation/terminology.md`：術語表（446 條）。表上有的術語一律照用；「不用」欄的寫法不得出現；狀態 `[並列]` 的術語在**本章**第一次出現時寫成「中文（English）」。
4. `zh-tw/chapter_8.md` 與 `zh-tw/chapter_13.md`：已審閱通過的兩章譯稿，作為語氣、句型與格式的範例。

## 翻譯方式：複製原稿後逐段替換

**不要從頭重打整章。**請這樣做：

1. `cp upstream/<檔案> zh-tw/<檔案>`
2. 用 Edit 工具把英文段落逐段（或一小節一小節）換成中文。`old_string` 取英文原文、`new_string` 寫中文。
3. 下列內容**一律不動**，讓它們保持與原稿逐位元組相同：
   - ```` ``` ```` 程式碼區塊的全部內容，包括其中的英文註解、輸出與空白
   - 行內程式碼（反引號內的文字）
   - `<math>…</math>` MathML 公式
   - 圖片行 `![…](images/…)` 的路徑（替代文字可以翻譯）
   - 連結的網址（連結文字要翻譯）
   - 註腳標記 `[^1]` 與定義行開頭的 `[^1]:`（定義內容要翻譯）
4. 如果某段 Edit 對不上（例如原文有特殊字元），可以改用較短的 `old_string`；真的不行才用 Bash heredoc（分隔字串要獨特）。

## 必須遵守的結構規則（`scripts/check-translation.rb` 會檢查）

- **一段對一段**：段落數、清單項目數必須與原稿相同；不合併、不拆段，不增刪空行造成的段落。
- **標題**：數量、層級、順序與原稿相同，只翻譯文字。章標題寫成 `# 第 N 章　中文標題`（中間是全形空白）；前言寫成 `# 前言`。
- **圖說**：圖片下一段的 `Figure 4-1. 說明` 寫成 `圖 4-1. 說明`。
- **表格標題**：`**Table 5-1. …**` 寫成 `**表 5-1. …**`；表格的欄數、列數不變，翻譯儲存格文字（程式碼與數值不動）。
- **範例標題**：`**Example 4-1. …**` 寫成 `**範例 4-1. …**`。
- **提示框**：`> **Note**`、`> **Tip**`、`> **Warning**` 寫成 `> **備註**`、`> **提示**`、`> **警告**`，其餘結構（`>` 前綴、空行）照原稿。
- **交互參照**：內文的「Chapter 7」寫成「第 7 章」、「Figure 4-1」寫成「圖 4-1」、「Table 5-1」寫成「表 5-1」、「Example 4-1」寫成「範例 4-1」。連結 `[Chapter 7](./chapter_7.md)` 保留網址，文字改成「第 7 章」。
- **人稱**：原文的 you 一律譯「你」，**不用「您」**。
- **用語**：台灣繁體中文與台灣慣用詞（程式碼、網路、資料、介面、預設、軟體……），不用中國大陸用語。檢查腳本若擋下某個詞在一般語境的正當用法（例如「簽名」指親筆簽名），請改寫句子，不要保留被擋的詞。
- **介面文字**：按鈕、欄位、選單等介面上的英文名稱保留英文；圖片的替代文字比照第 8、13 章保留英文即可。

## 術語表沒有的詞

術語表上沒有、而且需要決定譯名的術語：**保留英文**，並在該詞**第一次出現**的地方加上標記（之後出現時保留英文、不再標記），例如：

```
……使用 blob TODO-term: blob sidecar（建議：blob 附帶資料）……
```

格式固定為 `TODO-term: 英文術語（建議：你提議的中文）`。不要自己決定譯名後直接使用，也**不要修改 `translation/terminology.md`**；所有 TODO-term 會在全書譯完後統一決定、回填。
一般英文單字、專有名詞（人名、公司、產品、協議名稱，例如 Uniswap、EigenLayer、Geth）照慣例保留英文即可，不需要標 TODO-term。

## 譯註

只有在原文有**可以從本書內容或程式碼本身驗證**的錯誤或不精確時，才加譯註：照原文翻譯，再加一個譯註註腳，例如在句末加 `[^tn1]`，並在該段後面空一行寫 `[^tn1]: 譯註：……`。譯註註腳不列入結構比對。

**不要在譯註裡加入憑記憶得知的外部事實**（新聞、判決、日期、後續發展、數據更新）。如果你認為原文的資訊可能過時或有誤、但無法從書本身驗證，寫進筆記檔的「可能過時或需查證」一節，不要寫進譯文。

## 完成條件

1. 執行 `ruby scripts/check-translation.rb <檔案>`，必須顯示 `OK`。只剩 TODO-term 警告是可以的；其他任何 ✗ 都要修到通過。
2. 寫筆記檔 `translation/notes/<檔案>`（例如 `translation/notes/chapter_9.md`），內容：
   - 所有 TODO-term：英文、建議譯名、出現次數
   - 加了哪些譯註、為什麼（說明如何從書或程式碼驗證）
   - 可能過時或需查證：你懷疑原文有誤或過時、但沒有寫進譯註的地方
   - 翻譯時的疑問或不確定之處
   - 最後一次 `check-translation.rb` 的完整輸出（原樣貼上）
3. 最後用繁體中文回報：完成與否、TODO-term 數量、譯註數量、需要注意的地方。

## 禁止事項

- 不要修改 `zh-tw/<你的檔案>` 與 `translation/notes/<你的檔案>` 以外的任何檔案。
- 不要執行任何 git 指令，也不要執行 `scripts/build-site.rb`。
- 不要刪改程式碼區塊、MathML、圖片路徑、網址、註腳標記。
