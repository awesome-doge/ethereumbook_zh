# 《精通以太坊》第二版 翻譯風格指南

本指南規範第二版繁體中文譯稿的寫法。文字風格沿用《精通比特幣》第三版譯本的[風格指南](https://github.com/awesome-doge/bitcoinbook-3nd-zh/blob/main/translation/style-guide.md)；
不同的是，第二版翻譯的是 **Markdown**，而且譯稿必須和上游原稿逐段對齊，所以多了「結構規則」一節。

## 核心原則

1. **忠實**：準確傳達原文意思，不增刪內容；技術內容必須正確。
2. **可讀**：用自然的中文表達，長句適當拆開，被動句多改為主動。
3. **一致**：術語依 [`terminology.md`](terminology.md)；表上沒有的術語保留英文，並標 `TODO-term: 英文術語`。
4. **台灣用語**：使用台灣繁體中文與台灣慣用詞，不用中國大陸用語（程式碼不是代碼、網路不是網絡、資料不是數據、介面不是接口）。

## 結構規則（Markdown 譯稿）

譯稿放在 `zh-tw/`，檔名與 `upstream/` 相同。每次修改後執行：

```bash
ruby scripts/check-translation.rb chapter_8.md
```

以下規則都由這個腳本檢查，任何一項不符就無法合併：

| 項目 | 規則 |
|---|---|
| 標題 | 數量、層級與順序和原稿完全相同；只翻譯文字。章標題寫成 `# 第 8 章　智能合約與 Vyper`（「Chapter 8.」可改成「第 8 章」，網站會自動去掉） |
| 段落 | 一段對一段，不合併、不拆開，方便日後對照上游的修改 |
| 程式碼區塊 | **完全不動**，包括其中的英文註解、輸出結果與空白 |
| 行內程式碼 | 反引號內的內容不動；可以調整在句中的位置 |
| 連結 | 網址不動，只翻譯連結文字。指向其他章的連結（`./chapter_7.md`）保留，文字改成「第 7 章」 |
| 圖片 | 路徑不動；替代文字（`![…]`）用該圖的中文圖說（沒有圖說的自行翻譯） |
| 圖說 | 圖片下一段的「Figure 4-1. 說明」寫成「圖 4-1. 說明」，編號照原稿 |
| 表格與範例標題 | `**Table 5-1. …**` 寫成 `**表 5-1. …**`，`**Example 4-1. …**` 寫成 `**範例 4-1. …**`。原稿寫成標題的（第 2 章的 `##### Example 2-1. …`）照樣保留為標題：`##### 範例 2-1. …` |
| 全形符號 | 圖說與標題的編號後可以用半形句點加空格（`圖 4-1. 說明`）或全形句點（`圖 4-1．說明`） |
| 表格 | 欄數與列數不變，翻譯儲存格內的文字 |
| 提示框 | `> **Note**`、`> **Tip**`、`> **Warning**` 可以保留，或寫成 `> **備註**`、`> **提示**`、`> **警告**` |
| 註腳 | `[^1]` 標記與數量不變；譯者的補充寫成另一個註腳，內容以「譯註：」開頭（不列入比對） |
| 公式 | `<math>…</math>` 的 MathML **完全不動** |

## 文字規範

### 標點

- 中文句子使用全形標點：，。、；：？！「」『』（）
- 引號用「」，引號內再引用用『』；不用 "" 或 ''。
- 不用破折號（「——」「—」）。英文的 em dash 依語意改成逗號、括號、冒號，或拆成兩句；不要每處都換成同一種，句式要有變化。成對的術語用全形斜線：發布／訂閱、承諾／揭示。
- 刪節號用「……」。
- 數字範圍寫成「100 到 300 GB」「第 17 到 19 行」，不用「–」；數學的減號照原稿。
- 括號內全是英文或數字時，仍用全形括號：智能合約（smart contract）。

### 中英文混排

- 中文與英文、中文與數字之間加半形空格：使用 Solidity 0.8 編譯、需要 32 個 slot。
- 全形標點前後不加空格。
- 數字與單位之間加空格（百分比除外）：21 gwei、1 MB、50%。
- 大數字用千分位逗號：1,000,000 wei。

### 術語第一次出現

狀態為 `[並列]` 的術語，在每一章第一次出現時寫成「中文（English）」，之後只用中文：

```
權益證明（proof of stake，PoS）讓以太坊不再需要挖礦。之後的權益證明……
```

縮寫與全名並列時，順序為「中文（英文全名，縮寫）」。

### 人稱與語氣

- 原文的 you 一律譯成「你」，不用「您」（2026-11-03 決定；檢查腳本會擋「您」）。
- 原文的 we 照譯成「我們」。
- 保留原文的口語與幽默，但不要加入原文沒有的語氣詞。

### 交互參照

- 「Chapter 7」→「第 7 章」，「Figure 4-1」→「圖 4-1」，「Table 5-1」→「表 5-1」，「Example 4-1」→「範例 4-1」。
- 「in the previous section」等相對說法照意思翻譯即可。

### 譯註

原文有技術錯誤或需要補充臺灣讀者背景時，加一個以「譯註：」開頭的註腳，不要改動原文的意思。發現原文錯誤時也記錄在 `progress.md` 的備註欄，方便回報上游。

## 不翻譯的內容

- 程式碼、指令、輸出、變數與函式名稱、檔名、網址
- 軟體、工具、函式庫、網路與升級的名稱：Geth、Foundry、OpenZeppelin、Sepolia、Dencun
- 標準與提案編號：EIP-1559、ERC-20
- 圖片中的英文

## 審校檢查清單

- [ ] `ruby scripts/check-translation.rb <檔名>` 通過，沒有錯誤
- [ ] 沒有剩下 `TODO-term:`（或已列入術語表待決清單）
- [ ] 沒有疑似未翻譯的段落
- [ ] 術語符合 `terminology.md`，第一次出現時有中英並列
- [ ] 標點全形、中英文之間有空格
- [ ] 讀起來是通順的中文，不是逐字直譯
- [ ] 技術內容正確；有疑問的地方加上譯註或在 `progress.md` 註記
